# Skill: 미니퀴즈 생성

## 1. 스킬 정의

### 이름
미니퀴즈 생성

### 역할
이해도검증 완료 후, **현재 스텝의 개념만 확인하는 짧은 1개 문제를 생성**하여 학생의 이해도를 정량적으로 평가하는 스킬

### 활용 시점
- 자기말 설명 기반 이해도검증에서 "이해완료" 판정받은 후
- 각 스몰스텝마다 반복 (Step 1 → Step 2 → Step 3 ...)

### 입력값
- 현재 스텝 (current_step)
- 현재 개념 (current_concept)
- 학습목표 (learning_objective)
- 학생의 관심사 (INTERESTS) - 선택사항

### 출력값
- 1개의 미니퀴즈 (정답/해설은 내부만 저장)
- QUESTION_ID (식별자)
- ANSWER_KEY (정답)
- SCORING_CRITERIA (채점 기준)

---

## 2. 핵심 원칙

| 원칙 | 설명 | 위반 예시 |
|------|------|---------|
| **1개 문제** | 절대 2개 이상 금지 | ❌ "이 5개를 풀어봐" |
| **현재 스텝만** | 이미 배운 것 또는 다음 것 섞지 않기 | ❌ Step 2를 배우는데 Step 1, 2, 3 섞기 |
| **짧은 문장** | 문제 문장은 3줄 이내 | ❌ "지난시간에 배운 분수는..." (5줄) |
| **정답/해설 숨기기** | 학생에게만 문제 제시, 내부만 정답 | ❌ "정답은 1번입니다" |
| **원문 금지** | 교재 문제 그대로 복사 금지 | ❌ 교과서 pp.45 문제 복사 |
| **템플릿 참고** | question-template.csv 구조 따르기 | ✅ (객관식/주관식/빈칸 등) |
| **짧은 답변** | 한 단어 또는 선택지로 답할 수 있게 | ❌ "설명해봐" (장문 요구) |

---

## 3. 절차 (Step-by-Step)

### Step 1: question-template에서 현재 개념 관련 템플릿 찾기

**목표**: 이미 설계된 문제 구조 활용

**데이터 출처**: `question-template-bank.csv`

**템플릿 형식**:
```csv
concept_id,question_type,template_structure,example,difficulty
FRAC_001,multiple_choice,"[A]과 [B] 중 어느 것이 더 [C]?",1/2과 1/4 중 어느 것이 더 클까?,easy
FRAC_002,fill_blank,"[A]는 [B]를 나타낸다","1/4에서 1은 ___를 나타낸다",easy
FRAC_003,true_false,"[A]이다. (O/X)","1/2은 1/4보다 크다 (O/X)",easy
```

**조회 조건**:
```
SELECT * FROM question_template 
WHERE concept_id = CURRENT_CONCEPT 
  AND difficulty = (일반적으로 easy/medium)
```

---

### Step 2: 현재 스텝에 맞는 문제 유형 선택

**목표**: 스텝의 학습목표와 일치하는 문제 유형 결정

**문제 유형 선택 가이드**:

| 학습목표 타입 | 추천 문제 유형 | 예시 |
|-----------|----------|------|
| 개념 이해 | 객관식(선택) | "1/2과 1/4 중 크기가 더 큰 건?" |
| 용어 파악 | 빈칸 또는 객관식 | "위 숫자를 ___라고 합니다" |
| 기본 계산 | 객관식 또는 단답형 | "1/2 + 1/2 = ?" |
| 개념 적용 | 객관식 또는 상황문제 | "초콜릿을 4조각으로 나누고..." |
| 참/거짓 | True/False (O/X) | "1/3은 1/2보다 크다 (O/X)" |

---

### Step 3: 현재 개념만 확인하는 질문 작성

**목표**: 정확히 현재 스텝의 개념만 테스트

**주의**:
```
❌ Step 2 (분자/분모)를 배우는데
   "1/2 + 1/3을 계산하면?" (Step 4의 내용)
   
✅ Step 2 (분자/분모)를 배우는데
   "1/4에서 위의 숫자는 뭐라고 부를까?"
```

**작성 방법**:
1. 학습목표 다시 읽기
2. 핵심 키워드 3~5개 추출
3. 핵심만 물어보는 간단한 문장 작성
4. 답변 형식 결정 (선택/단답/O X)

**예시**:

```
Step 1: 분수 개념
학습목표: "전체를 같은 크기로 나눈 것 중 하나를 분수라고 한다"
핵심: 전체, 나누기, 같은크기, 부분

질문 1 (객관식):
"호빵을 4등분했을 때, 그 중 1개를 뭐라고 하는지 고르면?"
① 1/4 ② 1 ③ 4

질문 2 (빈칙):
"전체를 같은 크기로 나누고, 그 중 일부를 나타내는 수를 ___라고 한다"

질문 3 (O/X):
"호빵을 여러 개의 다른 크기로 나눈 것도 분수라고 할 수 있다 (O/X)"
```

---

### Step 4: 문제 문장을 짧게 쓰기

**목표**: 이해할 수 없는 만큼 짧게, 하지만 명확하게

**길이 기준**: 
- 문제: 3줄 이내
- 선택지: 각 1줄 이내

**개선 예시**:

```
❌ (길고 복잡)
"지난시간에 우리가 배운 분수라는 개념은 
 전체를 같은 크기로 나누었을 때 그 중 일부를 나타내는 수인데, 
 호빵을 4등분했을 때 그 중 1개를 뭐라고 부를까?"

✅ (짧고 명확)
"호빵을 4등분했을 때, 그 중 1개는?"
① 1/4   ② 1   ③ 4
```

---

### Step 5: 정답과 해설은 내부에만 저장

**목표**: 학생에게는 문제만 보이고, 정답/해설은 시스템 내부 저장

**저장 구조**:
```json
{
  "question": "호빵을 4등분했을 때, 그 중 1개는?",
  "options": ["1/4", "1", "4"],
  "answer_key": "1/4",  // 내부 저장만
  "explanation": "...",  // 내부 저장만
  "shown_to_student": {
    "question": "호빵을 4등분했을 때, 그 중 1개는?",
    "options": ["1/4", "1", "4"]
    // 정답/해설 없음
  }
}
```

---

### Step 6: 교재 문제 원문을 그대로 복사하지 않기

**원칙**: processed 데이터의 템플릿을 바탕으로 새 문제 생성

**구분**:

| 금지 | 허용 |
|------|------|
| "교과서 p.45 문제 1번 그대로" | "같은 개념의 새로운 상황" |
| "사과 5개, 3개는..." (원문) | "호빵을 4등분, 1개는..." (변형) |
| 교재 그림/표 복사 | 같은 개념의 다른 예시 |

**확인 방법**:
```
작성한 문제가:
✅ misconception-bank에 있는 오개념을 포함했는가?
✅ question-template의 구조를 따랐는가?
✅ 학생 관심사로 상황을 구성했는가?
❌ 교과서 원문과 같지 않은가?

모두 만족하면 사용 가능
```

---

### Step 7: question-template 구조를 참고해 새 문제 만들기

**템플릿 활용**:

```json
{
  "concept_id": "FRAC_002",
  "concept_name": "분자와 분모",
  "question_type": "fill_blank",
  "template": "[A]에서 위의 [B]을 ___라고 부르고, 
              아래의 [C]을 ___라고 부른다",
  "example": "1/4에서 위의 1을 분자라고 부르고,
            아래의 4를 분모라고 부른다"
}

적용:
[A] = 1/4
[B] = 1
[C] = 4

생성된 문제:
"1/4에서 위의 1을 ___라고 부르고,
 아래의 4를 ___라고 부를까?"
답: 분자, 분모
```

## 4. 문제 유형별 가이드

### 유형 1: 객관식 (Multiple Choice)

**특징**: 선택지 3~4개, 명확한 정답 1개

**사용 시점**: 개념 선택, 비교/구분

**예시**:
```
[Step 1: 분수 개념]

Q: 호빵을 4등분했을 때, 그 중 1개를 뭐라고 할까?
① 1/4
② 1/1
③ 4/1

정답: ① 1/4
```

---

### 유형 2: 빈칙 (Fill in the Blank)

**특징**: 한 단어 또는 짧은 답변

**사용 시점**: 용어 확인, 개념 완성

**예시**:
```
[Step 2: 분자와 분모]

Q: 1/4에서 위의 숫자 1을 ___라고 부릅니다

정답: 분자

기대 답변 형식: "분자", "위 숫자", "분자야" 등 허용
```

---

### 유형 3: True/False (O/X)

**특징**: 참/거짓만 판정

**사용 시점**: 개념 변별, 오개념 확인

**예시**:
```
[Step 3: 분수 크기 비교]

Q: 1/2이 1/4보다 크다 (O/X)

정답: O

학생이 X라고 답하면?
→ 오개념 감지
→ "조금 다르게 생각해보자. 호빵을..."
```

---

### 유형 4: 단답형 (Short Answer)

**특징**: 한 단어 또는 짧은 문장

**사용 시점**: 계산, 간단한 설명

**예시**:
```
[Step 4: 같은 분모 분수의 덧셈]

Q: 1/2 + 1/2은?

정답: 1 (또는 2/2, "1입니다" 등 허용)
```

---

### 유형 5: 상황문제 (Situational)

**특징**: 실제 상황에 개념 적용

**사용 시점**: 개념 응용

**예시**:
```
[Step 1: 분수 개념]

Q: 축구 선수 11명 중 5명이 경기에 나갔어.
   경기에 나간 선수가 전체의 몇 분의 몇일까?

정답: 5/11
```

## 5. 출력 형식

```
[학생에게 보이는 미니퀴즈만]
[선택지 또는 답변 방식 제시]

예) "이 문제를 풀어보면 될 것 같아. 천천히 생각해봐."

---
QUESTION_ID: [문제ID]
ANSWER_KEY: [정답]
SCORING_CRITERIA: [채점 기준]
STATUS: 미니퀴즈 생성 완료
NEXT: 학생의 답변 대기
STATE_UPDATE:
{
  "current_step": 정수,
  "current_concept": "개념명",
  "question_id": "ID",
  "question_text": "문제 텍스트",
  "question_type": "multiple_choice|fill_blank|true_false|short_answer|situational",
  "template_source": "question-template-bank.csv",
  "difficulty_level": "easy|medium",
  "learning_objective": "학습목표",
  "answer_key": "정답",
  "alternative_answers": ["대체답1", "대체답2"],
  "explanation": "정답 설명",
  "misconception_addressed": ["오개념1", "오개념2"],
  "student_interests_used": boolean,
  "scoring_criteria": {
    "full_point": 조건,
    "partial_point": 조건,
    "no_point": 조건
  },
  "ready_for_student_response": true,
  "next_state": "채점대기"
}
```

## 6. 필드 상세 설명

| 필드 | 설명 | 예시 |
|------|------|------|
| **QUESTION_ID** | 문제 식별자 (고유값) | "Q_FRAC_002_001" |
| **ANSWER_KEY** | 정답 (학생에게 숨김) | "1/4" |
| **SCORING_CRITERIA** | 채점 기준 | {full_point: "정답", partial_point: "유사답"} |
| **question_type** | 문제 유형 | "multiple_choice" |
| **template_source** | 템플릿 출처 | "question-template-bank.csv" |
| **difficulty_level** | 난이도 | "easy" |
| **alternative_answers** | 수용 가능한 대체 답변 | ["분자", "위 숫자"] |
| **explanation** | 정답 설명 (내부용) | "1/4는..." |
| **misconception_addressed** | 이 문제로 감지할 오개념 | ["분모 크기 혼동"] |
| **student_interests_used** | 관심사 포함 여부 | true |
| **scoring_criteria** | 채점 기준 명시 | {full_point: 정확한 정답만} |

## 7. 진도별 미니퀴즈 예시

### 예시 1: 중1 수학 - 분수의 덧셈 (Step 1)

**현재 Step**: 1
**현재 개념**: 분수 개념
**학습목표**: "전체를 같은 크기로 나눈 것 중 하나를 분수라고 한다"

**학생 관심사**: ["축구"]

**생성된 미니퀴즈**:
```
축구 경기가 45분씩 2개의 반으로 나뉜대.
그럼 전반 45분은 전체 경기의 몇 분의 몇일까?

① 1/2
② 45/90
③ 2/45

---
QUESTION_ID: Q_FRAC_CONCEPT_001
ANSWER_KEY: ① 1/2 (또는 45/90도 동등)
SCORING_CRITERIA: 
{
  "full_point": "1/2 또는 동등한 분수(45/90 등)",
  "partial_point": "45(분자만) 또는 2(분모만)",
  "no_point": "그 외"
}
question_type: situational
student_interests_used: true
misconception_addressed: ["분모를 전체 분을 나눈 개수로 안 봄"]
```

---

### 예시 2: 중1 수학 - 분자와 분모 (Step 2)

**현재 Step**: 2
**현재 개념**: 분자와 분모
**학습목표**: "분자는 위, 분모는 아래. 분자는 취한 부분, 분모는 전체 개수"

**학생 관심사**: ["게임"]

**생성된 미니퀴즈**:
```
1/4에서 위의 1을 ___라고 부르고,
아래의 4를 ___라고 부를까?

(한 단어씩 써도 돼)

---
QUESTION_ID: Q_FRAC_PARTS_001
ANSWER_KEY: 분자, 분모
SCORING_CRITERIA:
{
  "full_point": "분자, 분모 (또는 위 숫자, 아래 숫자)",
  "partial_point": "하나만 맞음",
  "no_point": "모두 틀림"
}
question_type: fill_blank
student_interests_used: false
misconception_addressed: ["분자와 분모 뒤바뀜"]
```

---

### 예시 3: 중1 국어 - 부사절 접속사 (Step 2)

**현재 Step**: 2
**현재 개념**: 접속사 "~서" (이유)
**학습목표**: "'~서'는 앞뒤의 이유를 연결하는 접속사"

**생성된 미니퀴즈**:
```
"비가 와서 우산을 쓴다"에서 
'와서'의 역할은 뭔가?

① 이유
② 대조
③ 시간

---
QUESTION_ID: Q_CONJ_001
ANSWER_KEY: ① 이유
SCORING_CRITERIA:
{
  "full_point": "① (또는 '이유'라고 말함)",
  "no_point": "② 또는 ③"
}
question_type: multiple_choice
misconception_addressed: ["접속사 역할 혼동"]
```

---

### 예시 4: 중1 영어 - 과거형 (Step 1)

**현재 Step**: 1
**현재 개념**: 규칙동사 과거형
**학습목표**: "규칙동사는 기본형 뒤에 -ed를 붙이면 과거형"

**생성된 미니퀴즈**:
```
"play"의 과거형은?

① plays
② played
③ plays

(나머지 선택지는 혼동 가능한 형태)

---
QUESTION_ID: Q_PAST_RULE_001
ANSWER_KEY: ② played
SCORING_CRITERIA:
{
  "full_point": "② (또는 'played'라고 쓰면 됨)",
  "no_point": "① 또는 ③"
}
question_type: multiple_choice
misconception_addressed: ["3인칭 단수와 과거형 혼동"]
```

- [ ] 교재 원문을 그대로 복사하지 않았는가?
- [ ] question-template 구조를 참고했는가?
- [ ] 문제 유형(객관식/빈칙/O X 등)을 명시했는가?
- [ ] 정답을 명확히 했는가?
- [ ] 채점 기준을 상세히 했는가?
- [ ] 대체 답변 형식을 허용했는가?
- [ ] STATUS를 "미니퀴즈 생성 완료"로 설정했는가?
- [ ] NEXT를 "학생의 답변 대기"로 설정했는가?

## 9. 주의사항

### 하면 안 되는 것

| 금지 사항 | 이유 |
|---------|------|
| 2개 이상의 문제 출제 | 마이크로러닝 위배, 인지 부하 ↑ |
| 다음 스텝 내용 포함 | Step 2인데 Step 3 내용 물어보기 |
| 길고 복잡한 문제 문장 | 개념 이해가 아니라 문제 이해 테스트 |
| 정답을 학생에게 말하기 | "정답은 1번입니다" (비채점) |
| 교과서 문제 그대로 복사 | 지적재산권, 창작성 위배 |
| 계산 문제만 | 개념 이해 테스트가 아님 |
| 모호한 선택지 | "거의 맞다", "가까운" 같은 모호한 표현 |

### 해야 하는 것

| 권장 사항 | 효과 |
|---------|------|
| 정확히 1개 문제 | 집중력, 명확성 |
| 현재 스텝만 | 현재 이해도 정확 측정 |
| 짧고 명확한 문장 | 문제 이해도 ↓ |
| 정답/해설 숨기기 | 공정한 채점 |
| 템플릿 기반 생성 | 일관성, 신뢰성 |
| 대체 답변 허용 | 학생 친화적 채점 |
| 오개념 감지 설정 | 오답 분석 용이 |

## 10. 문제 유형별 선택 기준

```
개념 기본 이해?
→ 객관식 또는 O/X

용어 확인?
→ 빈칙

개념 적용?
→ 상황문제

계산?
→ 단답형
```

## 11. 채점 기준 작성 팁

```
좋은 채점 기준:
{
  "full_point": "1/4 (또는 동등한 형태 4/16 등)",
  "partial_point": "분자만 답 또는 분모만 답",
  "no_point": "그 외"
}

나쁜 채점 기준:
{
  "full_point": "정답",
  "no_point": "오답"
}
← 너무 단순, 대체 답변 미반영
```

## 12. question-template 활용 예시

```json
[Template from question-template-bank.csv]
{
  "template": "[A]과 [B] 중 어느 것이 더 [C]?",
  "example": "1/2과 1/4 중 어느 것이 더 클까?"
}

[생성 과정]
[A] = 1/2 (개념 관련 수)
[B] = 1/3 (혼동 가능한 수)
[C] = 크다 (비교)

[최종 문제]
"1/2와 1/3 중 어느 것이 더 클까?"
```
