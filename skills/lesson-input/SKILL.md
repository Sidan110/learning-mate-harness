# Skill: 진도입력 정리

## 1. 스킬 정의

### 이름
진도입력 정리

### 역할
학생이 말한 **오늘의 학년, 과목, 페이지, 단원, 진도**를 하네스가 사용할 수 있는 **구조화된 데이터**로 정리한다.

### 활용 시점
- 라포형성 완료 후
- 학생이 "오늘 수학 분수 배웠어" 같은 학습 내용을 언급했을 때

### 입력값
- 학생의 자연스러운 진도 설명 (비구조화)

### 출력값
- 정규화된 진도 정보 (구조화)
- Processed 데이터와 매핑된 개념ID 및 학습목표

---

## 2. 핵심 원칙

| 원칙 | 설명 | 예시 |
|------|------|------|
| **정규화** | 학생의 자유로운 표현을 구조화 | "분수 더하기" → SUBJECT: 수학, UNIT: 분수의 덧셈 |
| **데이터 검증** | Processed 데이터와 반드시 매핑 | 데이터 없으면 "부족하다"고 명시 |
| **명확한 확인** | 애매하면 추가 질문 | "수학 몇 쪽이었어?" |
| **임의 생성 금지** | 없는 진도를 만들지 않음 | 중1 수학만 지원 범위 내 |
| **자연스러운 대화** | 정보 수집이 드러나지 않음 | 질문지 톤 피하기 |

---

## 3. 절차 (Step-by-Step)

### Step 1: 학교급 확인

**목표**: 초등학생 vs 중학생 구분

**확인 방법**:
- 학생이 미리 말한 경우: 데이터 활용
- 불명확한 경우: "혹시 초등학교야, 중학교야?"

**필드**: `SCHOOL_LEVEL`
- "초등" 또는 "중등"

**예시**:
```
학생: "저 3학년인데..."
→ 추가 질문 필요: "초등학교? 중학교?"

학생: "중학교 3학년인데..."
→ 명확함: SCHOOL_LEVEL = "중등", GRADE = "3학년"
```

---

### Step 2: 학년 확인

**목표**: 정확한 학년 파악

**확인 방법**:
- 학생이 이미 말했으면 확인 반복
- "3학년 맞지?"
- 불명확하면: "몇 학년이었어?"

**필드**: `GRADE`
- "1학년", "2학년", "3학년", "4학년", "5학년", "6학년" (초등)
- "1학년", "2학년", "3학년" (중등)

**예시**:
```
학생: "초등학교 4학년이에요"
→ GRADE = "4학년"

학생: "3학년인데..."
→ SCHOOL_LEVEL 먼저 확인 후 GRADE 설정
```

---

### Step 3: 과목 확인

**목표**: 지원 과목 범위 내 확인

**지원 과목**:
- 국어
- 영어
- 수학

**확인 방법**:
- "어떤 과목이었어?"
- "수학 맞지?"

**필드**: `SUBJECT`
- "국어", "영어", "수학" 중 하나

**미지원 과목 대응**:
```
학생: "과학이요"
→ "아, 과학이구나. 지금은 국어, 영어, 수학만 지원하고 있어. 
   수학이나 국어, 영어 중에 복습할 게 있어?"
```

---

### Step 4: 페이지 범위 또는 단원명 확인

**목표**: 학습 범위를 페이지 또는 단원 정보로 파악

**확인 방법 A - 페이지로 알려준 경우**:
```
학생: "45쪽부터 48쪽까지"
→ PAGE_RANGE = "45-48"
```

**확인 방법 B - 단원명으로 알려준 경우**:
```
학생: "분수의 덧셈을 배웠어"
→ UNIT = "분수의 덧셈"
```

**확인 방법 C - 모호한 경우**:
```
학생: "수학 이번 단원"
→ "혹시 몇 쪽쯤이었어?" 또는 "단원 이름이 뭐였어?"
```

**필드**:
- `PAGE_RANGE`: "45-48" 형식
- `UNIT`: "분수의 덧셈" 형식

---

### Step 5: Processed 데이터에서 해당 진도 찾기

**목표**: 데이터베이스 조회

**조회 로직**:
```
SELECT * FROM curriculum 
WHERE 
  school_level = SCHOOL_LEVEL 
  AND grade = GRADE 
  AND subject = SUBJECT 
  AND (page_range = PAGE_RANGE OR unit = UNIT)
```

**데이터 출처**:
- `curriculum-page-map.csv` (페이지 ↔ 진도 매핑)
- `curriculum-concepts.csv` (개념 정의)
- `lesson-units.json` (학습 단위)

---

### Step 6: 데이터가 없으면 부족이라고 명시

**원칙**: **절대 임의로 만들지 않음**

**대응 방법**:
```
학생: "고등학교 1학년 수학"
→ 초·중학교 범위 벗어남
→ "현재 초등학교와 중학교만 지원하고 있어. 
   미안해. 혹시 초등이나 중학 수학이 있어?"

학생: "중1 수학 삼각형 단원"
→ 데이터 확인 후 없으면
→ "중1 수학 삼각형 단원은 현재 데이터가 부족해. 
   다른 단원을 복습할까?"
```

**필드 처리**:
- 데이터가 없으면: 전체 STATE_UPDATE의 `data_available` = false
- 학생에게는 자연스럽게 다른 선택지 제시

---

### Step 7: 진도, 개념ID, 학습목표 정리

**목표**: Processed 데이터로부터 다음 정보 추출 및 정렬

**필드**:

| 필드 | 설명 | 예시 |
|------|------|------|
| **LESSON** | 진도명 | "분수의 덧셈" |
| **CONCEPT_IDS** | 이 진도에 속한 개념ID 배열 | ["CONCEPT_FRAC_001", "CONCEPT_FRAC_002"] |
| **LEARNING_GOAL** | 이 진도의 학습목표 | "분자끼리 더하고 분모는 같게 유지하기" |

**추출 예시**:
```json
{
  "LESSON": "분수의 덧셈",
  "CONCEPT_IDS": ["CONCEPT_FRAC_ADDITION_001", "CONCEPT_FRAC_ADDITION_002"],
  "LEARNING_GOAL": "같은 분모를 가진 분수끼리 덧셈하기"
}
```

---

### Step 8: 다음 단계는 수준진단으로 넘기기

**목표**: 상태 전이

**필드 설정**:
- `STATUS` = "진도정리 완료"
- `NEXT` = "수준진단으로 이동"
- `next_state` = "수준진단"

---

## 4. 확인 질문 예시

| 상황 | 질문 |
|------|------|
| 학년 불명확 | "좋아, 몇 학년 내용인지 알려줄래?" |
| 과목 불명확 | "수학이구나. 맞지?" |
| 페이지/단원 불명확 | "혹시 몇 쪽쯤 배웠는지도 알려줄래?" |
| 단원명 불명확 | "단원 이름이 뭐였어? 아니면 쪽수 알아?" |
| 여러 과목 언급 | "오늘은 그 중에 하나만 짧게 복습해보자. 뭐 먼저 할래?" |
| 지원 범위 벗어남 | "지금은 초중학교 국어, 영어, 수학만 지원하고 있어." |

## 5. 출력 형식

```
[학생에게 보이는 메시지]
[진도 정리 확인 및 다음 단계 안내]

---
SCHOOL_LEVEL: [초등/중등]
GRADE: [학년]
SUBJECT: [과목]
PAGE_RANGE: [페이지범위 또는 미지정]
UNIT: [단원명 또는 미지정]
LESSON: [진도명]
CONCEPT_IDS: [개념ID 배열]
LEARNING_GOAL: [학습목표]
STATUS: 진도정리 완료
NEXT: 수준진단으로 이동
STATE_UPDATE:
{
  "school_level": "초등|중등",
  "grade": "학년",
  "subject": "국어|영어|수학",
  "page_range": "45-48 또는 null",
  "unit": "진도명 또는 null",
  "lesson": "진도명",
  "concept_ids": ["ID1", "ID2", ...],
  "learning_goal": "목표 설명",
  "data_available": true|false,
  "data_source": "curriculum-concepts.csv|lesson-units.json",
  "status": "진도정리_완료",
  "next_state": "수준진단"
}
```

## 6. 데이터 매핑 예시

### 예시 1: 중1 수학 - 분수의 덧셈

**학생 입력**:
```
"중학교 1학년 수학인데 분수의 덧셈을 배웠어요"
```

**정규화 과정**:
1. SCHOOL_LEVEL = "중등"
2. GRADE = "1학년"
3. SUBJECT = "수학"
4. UNIT = "분수의 덧셈"

**데이터 조회** (curriculum-concepts.csv):
```
school_level=중등, grade=1, subject=수학, unit=분수의 덧셈
→ 데이터 발견 ✅
```

**결과**:
```
LESSON: "분수의 덧셈"
CONCEPT_IDS: ["FRAC_ADD_001", "FRAC_ADD_002", "FRAC_ADD_003"]
LEARNING_GOAL: "같은 분모를 가진 분수의 덧셈 계산하기"
```

**출력**:
```
그렇구나! 중1 수학 분수의 덧셈이군요. 
그 부분 함께 복습해보자.

---
SCHOOL_LEVEL: 중등
GRADE: 1학년
SUBJECT: 수학
PAGE_RANGE: null
UNIT: 분수의 덧셈
LESSON: 분수의 덧셈
CONCEPT_IDS: ["FRAC_ADD_001", "FRAC_ADD_002", "FRAC_ADD_003"]
LEARNING_GOAL: 같은 분모를 가진 분수의 덧셈 계산하기
STATUS: 진도정리 완료
```

## 7. 대화 흐름 시나리오

### Scenario 1: 명확한 진도 입력

```
[라포형성 완료 후]

AI: 그럼 오늘은 어떤 내용을 배웠어?

Student: 수학 중학교 1학년 분수 더하기요.

AI: 분수 더하기! 좋아. 혹시 몇 쪽 정도였어?

Student: 교과서 45쪽부터 48쪽까지요.

AI: 그렇구나! 중1 수학 분수의 덧셈, 45-48쪽이 맞지? 
그럼 이 부분 함께 복습해보자. 먼저 지금 이 내용을 어느 정도 알고 있는지 
간단히 물어봐도 될까?

---
SCHOOL_LEVEL: 중등
GRADE: 1학년
SUBJECT: 수학
PAGE_RANGE: 45-48
UNIT: 분수의 덧셈
LESSON: 분수의 덧셈
CONCEPT_IDS: ["FRAC_ADD_001", "FRAC_ADD_002", "FRAC_ADD_003"]
LEARNING_GOAL: 같은 분모를 가진 분수의 덧셈 계산하기
STATUS: 진도정리 완료
NEXT: 수준진단으로 이동
```

---

### Scenario 2: 모호한 진도 입력

```
[라포형성 완료 후]

AI: 그럼 오늘은 어떤 내용을 배웠어?

Student: 음... 수학인데... 어떤 거였는지 기억이 안 나는데요.

AI: 아, 그렇구나. 괜찮아. 혹시 교과서가 있어? 
그럼 어떤 단원이었는지 봐볼까. 아니면 "분수", "도형", "계산" 이런 식으로 뭔지 조금이라도 기억나는 게 있어?

Student: 아, 맞다. 분수! 분수 더하기요.

AI: 분수 더하기! 좋아. 그럼 중학교맞지? 몇 학년?

Student: 네, 1학년이요.

AI: 중1 수학 분수의 덧셈이 맞지? 그럼 이 부분 함께 복습해보자.
```

### Scenario 3: 지원 범위 벗어남

```
[라포형성 완료 후]

Student: 과학인데... 별 배웠어요.

AI: 아, 과학이군요. 지금은 국어, 영어, 수학만 지원하고 있어. 미안해. 
그래도 수학, 국어, 영어 중에 오늘 배운 게 또 있어?

Student: 수학도 했어요! 분수 계산했어요.

AI: 그럼 수학 복습하자! 분수 계산... 중학생이니까 중1 맞지? 
분수의 덧셈이었나 뺄셈이었나?
```

## 8. 체크리스트

### 진도입력 정리 Skill 실행 체크

- [ ] 학교급을 명확히 확인했는가? (초등/중등)
- [ ] 학년을 정확히 확인했는가?
- [ ] 과목을 지원 범위 내에서 확인했는가? (국어/영어/수학)
- [ ] 페이지 또는 단원명을 확인했는가?
- [ ] Processed 데이터를 조회했는가?
- [ ] 데이터가 없으면 "부족하다"고 명시했는가? (임의 생성 금지)
- [ ] 진도, 개념ID, 학습목표를 정리했는가?
- [ ] STATUS를 "진도정리 완료"로 설정했는가?
- [ ] NEXT를 "수준진단"으로 설정했는가?
- [ ] 모든 필드를 출력했는가?

## 9. 주의사항

### 하면 안 되는 것

| 금지 사항 | 이유 |
|---------|------|
| 데이터 없을 때 임의로 진도 만들기 | 정확하지 않은 학습 피드백 제공 |
| 지원 범위 밖 과목 강제로 지원하기 | 커리큘럼 데이터 없음 |
| 진도 확인 생략하고 진행하기 | 잘못된 진도로 복습 진행 |
| 학생에게 "데이터가 없어서 못 해" 하고 끝내기 | 다른 선택지 제시 필요 |
| 학생이 말한 표현 그대로 UNIT에 저장하기 | 정규화된 진도명으로 저장 |
