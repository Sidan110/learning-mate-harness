# Skill: 수준진단

## 1. 스킬 정의

### 이름
수준진단

### 역할
오늘 진도에 대한 학생의 **현재 이해 수준을 파악**하여, **몇 번째 스텝부터 시작하면 좋을지 결정**하는 스킬

### 활용 시점
- 진도입력 정리 완료 후
- 학생의 학습 시작점을 결정하기 전

### 입력값
- SCHOOL_LEVEL, GRADE, SUBJECT, LESSON (진도입력에서 전달)
- 해당 진도의 선수개념 목록 (prerequisite-map.csv)

### 출력값
- START_LEVEL (1, 2, 3)
- DIAGNOSIS_RESULT (진단 결과 설명)

---

## 2. 핵심 원칙

| 원칙 | 설명 | 위반 예시 |
|------|------|---------|
| **시험 아닌 대화** | 편안한 톤, 정보 수집 느낌 | ❌ "자, 시험처럼 풀어봐" |
| **최소 질문** | 2~3개만 | ❌ 5개 이상 |
| **쉬운 난이도** | 선수개념 확인 수준 | ✅ "1/2과 1/4 중 크기가 더 큰 건?" |
| **다양한 형식** | 보기, 예/아니오, 한 단어 | ❌ "분수의 덧셈 규칙을 설명해봐" |
| **긍정 피드백** | 틀려도 부정 금지 | ❌ "틀렸어", "아니야" |
| **속도감** | 빠르게 진행 (길어지지 않기) | ❌ 5턴 이상 소요 |

---

## 3. 절차 (Step-by-Step)

### Step 1: 오늘 진도에 필요한 선수개념 확인

**목표**: 이 진도를 이해하기 위해 필수인 개념 파악

**데이터 출처**: `prerequisite-map.csv`

**예시**:
```
진도: 분수의 덧셈
필요한 선수개념:
  - 분수의 크기 비교
  - 분수의 개념 (분자/분모)
  - 같은 분모 분수
```

**진도별 선수개념 예시**:

| 진도 | 선수개념 |
|------|---------|
| 분수의 덧셈 | 분수 크기 비교, 분수 개념, 분모 이해 |
| 부사절 접속사 | 문장 구조, 주절/종속절 구분 |
| 동사의 과거형 | 동사 기본형, 시제 개념 |

---

### Step 2: 아주 쉬운 질문 2~3개만 낸다

**목표**: 선수개념 이해도를 빠르게 파악

**수량**: **정확히 2~3개** (길어지면 시험처럼 느껴짐)

**난이도**: **아주 쉬움**
- 교과서 기본 개념
- 학생이 "잘 모르면" 못 답할 수준 (불가능하지 않은 수준)

**예시 1 - 분수의 덧셈**:
```
질문 1 (보기형): 
"1/2과 1/4 중에 어느 게 더 클까?"
① 1/2    ② 1/4

질문 2 (예/아니오):
"1/3 + 1/3을 더하면 2/6이 되나요?"
① 네    ② 아니오

질문 3 (한 단어):
"분수에서 위의 숫자를 뭐라고 부르는지 알아?"
(기대 답변: 분자)
```

**예시 2 - 부사절 접속사**:
```
질문 1 (보기형):
"'나는 학교를 다니는데 친구를 만난다'에서 
 '는데'의 역할은?"
① 이유    ② 대조    ③ 시간

질문 2 (예/아니오):
"'그가 도움을 준다'는 주절이 될 수 있나?"
① 네    ② 아니오

질문 3 (한 단어):
"'~하기 때문에'는 어떤 접속사의 뜻이지?"
```

---

### Step 3: 질문 형식은 보기형, 예/아니오, 한 단어 수준

**목표**: 학생이 부담 없이 답할 수 있게 함

### 형식 A: 보기형 (객관식)
```
질문: "1/2과 1/4 중 어느 게 더 클까?"
① 1/2 (정답)
② 1/4

학생이 선택하기만 하면 됨 (작성 부담 없음)
```

### 형식 B: 예/아니오
```
질문: "분자와 분모는 다른 숫자인가?"
① 네 (정답)
② 아니오

선택지 매우 간단
```

### 형식 C: 한 단어 또는 짧은 답변
```
질문: "분수에서 위의 숫자를 뭐라고 부르는지 알아?"
(기대 답변: 분자, 위 숫자, 윗숫자 등)

여러 형태의 답변 허용
```

### 금지 형식:
```
❌ "분수의 덧셈이 뭔지 설명해봐"
   (너무 어려움, 글쓰기 부담)

❌ "왜 분자끼리 더할까?"
   (설명 요구)

❌ "계산 문제 5개를 풀어봐"
   (시험처럼 느껴짐)
```

---

### Step 4: 학생이 틀려도 부정적 표현을 쓰지 않는다

**원칙**: **절대로 부정적 표현 금지**

| 금지 표현 | 대체 표현 |
|---------|---------|
| "틀렸어" | "괜찮아, 처음에는 이렇게 헷갈릴 수 있어" |
| "아니야" | "다시 한 번 봐보자" |
| "또 틀렸어" | "아직 이 부분이 어렵구나" |
| "왜 몰라?" | "여기서 신경 써야 할 부분이 있어" |
| "틀린 거 찾아봐" | "이 부분이 조금 다를 수 있어" |

**올바른 대응**:
```
학생: "1/2 + 1/2 = 2/4예요"

AI (부정적 표현):
❌ "틀렸어. 1/2 + 1/2은 1이야"

AI (긍정적 표현):
✅ "음, 분자는 잘 더했는데, 분모도 더하면 
   이상해질 수 있어. 분모는 같아야 한다고 생각해보자"
```

---

### Step 5: 정답 개수에 따라 START_LEVEL을 정한다

**목표**: 학습 시작점 결정

#### START_LEVEL 기준

| START_LEVEL | 정답 개수 | 의미 | 다음 스텝 |
|------------|---------|------|---------|
| **3** | 2~3개 모두 정답 | 거의 다 알고 있음 | 심화 개념으로 시작 |
| **2** | 1~2개 정답 | 일부만 알고 있음 | 기본 개념부터 정리 |
| **1** | 0~1개 정답 | 거의 모름 | 선수개념부터 강화 |

#### 정답 판정 기준

**엄격하지 않게 판정**:
- 답이 명확하지 않아도 "대체로 맞다"면 정답 처리
- 띄어쓰기, 표기법 차이는 무시
- 부분 정답도 정답으로 처리 가능

**예시**:
```
질문: "분수에서 위의 숫자를 뭐라고 부르는지 알아?"

학생 답변 1: "분자"
→ 정답 ✅

학생 답변 2: "윗숫자"
→ 정답 ✅ (표현만 다름)

학생 답변 3: "숫자"
→ 부분 정답 ✅ (불명확하지만 개념은 이해)

학생 답변 4: "모르겠어요"
→ 오답 ❌
```

## 4. 진단 결과별 대응

### START_LEVEL = 3 (거의 다 알고 있음)

**진단 결과**:
```
DIAGNOSIS_RESULT: "이 부분 대부분 이미 알고 있네요!"
```

**학생 메시지 톤**:
```
"좋아, 분수는 꽤 이해하고 있는 것 같은데. 
 그럼 이제 분수의 덧셈 규칙을 정확히 정리해보자."
```

**다음 진행**:
- 개념 설명 생략 가능
- 규칙/공식만 빠르게 정리
- 바로 미니퀴즈로 진행 가능

---

### START_LEVEL = 2 (일부만 알고 있음)

**진단 결과**:
```
DIAGNOSIS_RESULT: "분수는 이해하는데, 일부가 아직 명확하지 않네요."
```

**학생 메시지 톤**:
```
"분수의 크기는 이해했는데, 분자/분모 역할이 조금 
 헷갈릴 수 있겠네. 함께 정리해보자."
```

**다음 진행**:
- 기본 개념부터 천천히 정리
- 2~3개 스텝으로 분해
- 비유/예시 활용

---

### START_LEVEL = 1 (거의 모름)

**진단 결과**:
```
DIAGNOSIS_RESULT: "분수라는 개념이 아직 생소하네요. 
처음부터 차근차근 해보죠."
```

**학생 메시지 톤**:
```
"분수가 처음이거나 아직 어렵구나. 그럼 더 작은 조각으로 
 천천히 봐보자. 분수가 뭔지부터 시작할게."
```

**다음 진행**:
- 선수개념부터 먼저 강화
- 5~6개 스텝으로 세분화
- 실생활 비유 활용 (호빵 나누기, 초콜릿 등)

---

## 5. 출력 형식

```
[학생에게 보이는 진단 질문]
[자연스러운 대화 톤]

---
DIAGNOSIS_RESULT: [진단 결과 설명]
START_LEVEL: [1|2|3]
STATUS: 수준진단 완료
NEXT: 과제분석으로 이동
STATE_UPDATE:
{
  "lesson": "진도명",
  "prerequisite_concepts": ["개념1", "개념2", ...],
  "diagnosis_questions": [
    {
      "question": "질문 텍스트",
      "answer_type": "multiple_choice|yes_no|short_answer",
      "correct_answer": "정답",
      "student_answer": "학생 답변",
      "result": "correct|incorrect"
    },
    ...
  ],
  "correct_count": 정수,
  "total_questions": 정수,
  "start_level": 1|2|3,
  "diagnosis_result": "진단 결과",
  "next_state": "과제분석"
}
```

## 6. 필드 상세 설명

| 필드 | 설명 | 예시 |
|------|------|------|
| **DIAGNOSIS_RESULT** | 진단 결과를 학생이 이해할 수 있게 설명 | "분수는 이해하는데, 덧셈 규칙이 조금 어려워 보여요" |
| **START_LEVEL** | 1, 2, 또는 3 | 2 |
| **STATUS** | 현재 상태 | "수준진단 완료" |
| **NEXT** | 다음 단계 | "과제분석으로 이동" |
| **prerequisite_concepts** | 필요한 선수개념 배열 | ["분수 개념", "분모 이해", "분자 이해"] |
| **diagnosis_questions** | 질문별 상세 기록 | [{...}, {...}] |
| **correct_count** | 정답 개수 | 2 |
| **total_questions** | 총 질문 개수 | 3 |
| **start_level** | 시작 레벨 (숫자) | 2 |
| **diagnosis_result** | 진단 메시지 | "일부 개념 정리 필요" |

## 7. 진도별 진단 질문 예시

### 예시 1: 중1 수학 - 분수의 덧셈

**선수개념**: 분수 개념, 분자/분모, 분수 크기 비교

**질문**:
```
질문 1 (보기형 - 난이도: 최하):
"1/2과 1/4 중에 어느 게 더 클까요?"
① 1/2 (정답)
② 1/4

질문 2 (예/아니오 - 난이도: 최하):
"분수에서 '/'의 아래 숫자를 분자라고 할까요?"
① 네
② 아니오 (정답: 아니오, 분모)

질문 3 (한 단어 - 난이도: 최하):
"호빵 반개는 분수로 뭐라고 쓸까요?"
(기대 답변: 1/2, 반개)
```

**가능한 시나리오**:
```
학생이 3개 모두 정답 → START_LEVEL = 3
학생이 2개 정답 → START_LEVEL = 2
학생이 1개 정답 → START_LEVEL = 2
학생이 0개 정답 → START_LEVEL = 1
```

---

### 예시 2: 중1 국어 - 부사절 접속사

**선수개념**: 문장 구조, 주절/종속절, 문법 기초

**질문**:
```
질문 1 (보기형):
"'비가 와서 우산을 쓴다'에서 '~서'의 뜻은?"
① 이유 (정답)
② 대조
③ 시간

질문 2 (예/아니오):
"'학교를 가다'는 문장에서 '가다'는 동사인가?"
① 네 (정답)
② 아니오

질문 3 (한 단어):
"'~지만', '~는데', '~면'의 공통점은?"
(기대 답변: 접속사, 연결, 앞뒤 연결 등)
```

---

### 예시 3: 중1 영어 - 과거형

**선수개념**: 동사 기본형, 시제 개념, 규칙동사/불규칙동사

**질문**:
```
질문 1 (보기형):
"'play'의 과거형은?"
① played (정답)
② play
③ plays

질문 2 (예/아니오):
"모든 동사의 과거형이 '-ed'로 끝날까?"
① 네
② 아니오 (정답)

질문 3 (한 단어):
"'go' → 'went'처럼 규칙을 따르지 않는 동사는?"
(기대 답변: 불규칙동사, 불규칙 등)
```

## 8. 진단 과정 시나리오

### Scenario 1: 완벽한 이해 (START_LEVEL = 3)

```
AI: 자, 간단하게 몇 가지만 확인해볼까. 
    1/2과 1/4 중에 어느 게 더 클까요?

학생: 1/2이요.

AI: 좋아! 그럼 이 번째 질문. 분수에서 '/'의 
    아래 숫자를 분자라고 할까요?

학생: 아니요, 분모예요.

AI: 정확하네! 마지막 질문. 호빵 반개는 분수로 뭐라고 쓸까요?

학생: 1/2이요.

AI: 와, 분수를 정말 잘 이해하고 있네! 
    그럼 이제 분수의 덧셈 규칙을 정확히 정리해보자.

---
DIAGNOSIS_RESULT: 분수 개념을 잘 이해하고 있어요. 
덧셈 규칙을 정확히 배워봅시다.
START_LEVEL: 3
STATUS: 수준진단 완료
NEXT: 과제분석으로 이동
STATE_UPDATE:
{
  "correct_count": 3,
  "total_questions": 3,
  "start_level": 3,
  "diagnosis_result": "선수개념 완벽"
}
```

---

### Scenario 2: 일부 이해 (START_LEVEL = 2)

```
AI: 자, 간단하게 확인해볼까. 
    1/2과 1/4 중에 어느 게 더 클까요?

학생: 1/4요.

AI: 음, 다시 생각해봐. 호빵을 반으로 나눈 것이랑 
    4등분으로 나눈 것 중에 뭐가 더 클까?

학생: (다시 생각) 아, 1/2이요!

AI: 그래, 맞아! 그럼 이 번째. 분수에서 '/'의 
    아래 숫자를 분자라고 할까요?

학생: 네.

AI: 거의 맞는데, 이건 분모라고 해. 분자는 위에 있는 
    숫자야. 그럼 마지막 하나. 호빵 반개는 분수로 뭐라고 쓸까요?

학생: 1/2이요.

AI: 좋아! 분수는 대체로 이해하고 있는데, 분자/분모 
    역할만 한 번 더 정리해봅시다.

---
DIAGNOSIS_RESULT: 분수 개념은 이해하는데, 분자/분모가 
조금 헷갈리네요. 함께 정리해봅시다.
START_LEVEL: 2
STATUS: 수준진단 완료
NEXT: 과제분석으로 이동
STATE_UPDATE:
{
  "correct_count": 2,
  "total_questions": 3,
  "start_level": 2,
  "diagnosis_result": "일부 개념 강화 필요"
}
```

---

### Scenario 3: 거의 모름 (START_LEVEL = 1)

```
AI: 자, 간단하게 확인해볼까. 
    1/2과 1/4 중에 어느 게 더 클까요?

학생: 음... 모르겠어요.
```

## 9. 체크리스트

### 수준진단 Skill 실행 체크

- [ ] 선수개념을 확인했는가?
- [ ] 2~3개의 질문만 냈는가? (5개 이상 금지)
- [ ] 질문이 매우 쉬운가? (선수개념 확인 수준)
- [ ] 질문 형식이 다양한가? (보기형, 예/아니오, 한 단어)
- [ ] 학생의 틀린 답에 부정적 표현을 썼는가? (금지)
- [ ] START_LEVEL을 정확히 결정했는가?
- [ ] DIAGNOSIS_RESULT를 기록했는가?
- [ ] 학생에게는 시험 같은 느낌을 주지 않았는가?
- [ ] STATUS를 "수준진단 완료"로 설정했는가?
- [ ] NEXT를 "과제분석"으로 설정했는가?

## 10. 주의사항

### 하면 안 되는 것

| 금지 사항 | 이유 |
|---------|------|
| 5개 이상 질문 출제 | 시험처럼 느껴짐, 피로도 증가 |
| "자, 시험 시작" 같은 표현 | 심리적 거부감 |
| 틀린 답에 "틀렸어", "아니야" | 정서적 안전감 훼손 |
| 이미 알 것 같은데 계속 확인 | 시간 낭비 |
| 어려운 질문으로 "진짜 아는지 테스트" | 진단이 아닌 평가처럼 느껴짐 |
| 진단 결과를 학생에게 "레벨 1이네" 같이 말하기 | 낙인 효과 |

### 해야 하는 것

| 권장 사항 | 효과 |
|---------|------|
| 2~3개만 간단하게 | 부담 없는 진단 |
| 보기형/예아니오 중심 | 답변 부담 감소 |
| 틀려도 "괜찮아" | 정서적 안전감 |
| 학생의 정답 부분 칭찬하기 | 동기 유지 |
| 진단 결과를 긍정적으로 표현하기 | "생소한 부분을 함께 배워보자" |

## 11. START_LEVEL의 의미

### START_LEVEL = 3 (완벽)

```
의미: 이 진도의 선수개념을 이미 잘 알고 있음
다음 진행:
- 선수개념 설명 최소화
- 바로 핵심 개념 (덧셈 규칙)으로 진행
- 스텝 수를 2~3개로 단축 가능
```

### START_LEVEL = 2 (부분)

```
의미: 일부 개념은 알지만, 일부는 명확하지 않음
다음 진행:
- 약한 부분 집중 정리
- 스텝 수를 3~4개로 설정
- 약한 부분부터 시작
```

### START_LEVEL = 1 (거의 모름)

```
의미: 선수개념이 부족하거나 개념이 아직 낯설음
다음 진행:
- 선수개념부터 강화
- 스텝 수를 5~6개로 세분화
- 처음부터 천천히 진행
```
